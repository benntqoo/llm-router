## 1. 判据对照

**判据原文**（03 §1）：「一次流式请求后 UI 显示 **tokens / TTFT / tokens·s⁻¹ / 估算成本**，且 `usage_log.estimated` 标记正确（上游有 usage 时为 0）」

这一条里有 6 个可验证点，拆开逐条对：

| # | 子项 | 结论 | 证据 |
|---|---|---|---|
| ① | **一次流式请求**（前提） | ✅ **通过** | T14 真机：3 次**流式**请求 → 3 行 `usage_log`，`ttft_ms` = 185 / 186 / 201 ms（非空，说明流式 tee 抓到了末帧 usage） |
| ② | UI 显示 **tokens** | ✅ **通过** | T14 真机：KPI「总 token **229**（输入 188 · 输出 41）」+ 明细表逐行（51 / 51 / 51 / 38 / 38） |
| ③ | UI 显示 **TTFT** | ✅ **通过** | T14 真机：KPI「**TTFT P50 / P95 = 186 ms / 201 ms**」；明细表 185 / 186 / 201 ms；**非流式行显示「—」**（非流式没有"首个 token"的概念） |
| ④ | UI 显示 **tokens·s⁻¹** | ✅ **通过** | T14 真机：KPI「输出速度 **44.9 tok/s**」；明细表 36.3 / 34.2 / 36.6 tok/s——**按该行自己的耗时复算**（e2e 用例里断言 `tps == 输出 token ÷ 耗时秒`） |
| ⑤ | UI 显示 **估算成本** | ✅ **通过** | T14 真机：KPI「已知成本 **¥0.000221 元**」；明细表 ¥0.00006 / ¥0.000041 元；**未配牌价的那行显示「未知」而不是「¥0」**（02 §8.3 的 `0` / `NULL` 语义在 UI 上同样成立） |
| ⑥ | `usage_log.estimated` 标记正确（**上游有 usage 时为 0**） | ✅ **通过** | 5 行流水 `estimated` 全为 **0**（上游都给了 usage）；明细表「来源」列全为**精确**；KPI「估算行 **0**」。反向也成立：T12 的 e2e 证明上游**没回** usage 时该列为 1 |

**判据是怎么成立的**：请求经**真网关**打到真上游（mock，非直连）→ `usage_log` 落库 → 后端聚合 → IPC → UI 渲染，**全链没有手工数据**；UI 上每个数字都能在库里找到对应行。

**证据留档**：`docs/reviews/T14-usage-aggregation.md` §3.4（真机四张截图：`app-ui-usage.png` / `-channel` / `-model` / `-client`）、§3.2（e2e 全链）、§3.1（后端单测）、§3.3（前端单测）。

## 3. M2 期间顺带解决的（超出判据，但决定"能不能真自用"）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **真实上游实测**（T13） | OpenRouter 免费模型**真上游**：真实 token 数 → `cost_micros` 与**独立复算**逐笔一致（536 / 64 / 491 / 509 micros）。这把成本换算从"自造 mock"推进到"真上游"，也是本项目**第一次打通真实上游 HTTPS** |
| 2 | **修掉一条既有随机失败断言** | `gateway::auth` 断言 client key 长度**恒为 43**，实为 **42~43**（`base62_encode` 去前导零；首字节 < 4 时为 42，概率约 1.2%）→ 改区间断言，**连跑 40 次全绿**。纯测试改动、零行为变更 |
| 3 | **验收工具沉淀** | `cargo run --example seed_usage_demo`：种临时库（渠道 + 两个模型 + 一条价目 + 凭证 + client key）并起 mock 上游——用量/统计类真机验收从此**一键可复现** |

## 4. 已知限制与未做项

| 项 | 状态 | 说明 / 解除条件 |
|---|---|---|
| **价目表编辑 UI** | ❌ **未做** | T14 任务卡只写「四维聚合 + 图表」，M2 判据只需成本**可显示**（只读即可）。价目表的增删改仍走 `price_*` IPC（列 / 改 / 删 / 重算 / 试算都在）→ **另排一张卡**（T13 留档里"属 T14"的措辞以本条为准作废） |
| 多档定价（分段 / 峰谷 / priority 1.5 倍） | ⚠️ **表达不了** | `price` 表每模型只有一组三价；真要表达需改表结构（走提案）。见 02 §8.3 |
| `minimax_intl`（USD 计价） | ⚠️ **不预填** | 本表以元计价、**不做汇率折算** → 该 provider 的 `cost_micros` 保持 NULL（未知），用户可自行填行 |
| 缓存命中的上游报数 | ⚠️ **免费档不报** | OpenRouter 免费模型不报 `cached_tokens` → 实测三轮 `cache_read` 均为 0；**上游不报就不验，不强求**（02 §8.4） |
| 牌价时效 | ⚠️ **快照** | 预填价取自厂商官方页面，**核验于 2026-11-26**；厂商调价不会自动跟随（DeepSeek 刚在 2026-08-17 调过一次），每行可编辑 |
| 图表实现 | ⚠️ **手写 SVG** | 不引第三方图表库（与 02 §6.6 事件总线同一取向：轻量、可离线构建、包体不增，gzip 56.38 kB）；图表单独成 `src/usage/UsageChart.tsx`，**要换实现只动这一个文件** |
| M1 判据 ① 的**真实 DeepSeek** 一轮带工具调用的对话 | 🟡 **仍挂起** | 与 M2 无关，同一前提（头头 2026-11-26 决定"先不测真实上游"）；解除条件 = 拿到任一 A 类渠道真实 API Key——**同一把钥匙还能顺带解锁 T10 的 A 类 7 列真实矩阵** |
