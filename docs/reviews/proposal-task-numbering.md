## 1. 问题

`docs/planning/02-technical-design.md` 中的三处任务编号与 `docs/planning/03-delivery-plan.md`（任务卡真值源）对不上：

| 位置 | 02 文档中的编号 | 03 任务卡中的对应编号 | 指向的实际工作 |
|---|---|---|---|
| 02 §6.3 + §11-2 | `T18a`（WorkBuddy 协议抓包） | **T22** WorkBuddy 协议确认（抓包） | 同一件事 |
| 02 §6.2 第 4 步 | `T17`（Copilot 伪装头常量核实） | **T21** Copilot 出站适配 + 实测 | 同一件事 |
| 02 §6.5 | `T9`（pi 接入实测） | **T10** 实测矩阵（A 类 7 列 + pi 接入） | 同一件事 |

旁证：02 §6.3 自述"任务 T18a 确认"，而 03 §2 的 T18 是"M3 站点插件 ×2"，两者不可能是同一任务。

## 2. 根因判断

02 与 03 在 2026-11-25 同日成稿，02 写作时沿用了更早一版任务编号（T17/T18a/T9），03 成稿后编号被重排（新增 T22 抓包任务、T10 独立为实测矩阵），02 未同步。

## 3. 建议方案

**以 `03-delivery-plan.md` 为任务编号唯一真值源**，把 02 中的三处引用改为：

- 02 §6.3 第 1 条与 §11-2：`T18a` → `T22`
- 02 §6.2 第 4 步：`T17` → `T21`
- 02 §6.5 结尾段：`T9` → `T10`

理由：03 §2 是任务卡本体（目标/产出/验收/依赖齐备），且依赖图 §3、里程碑 §1 均与 03 自洽；02 是实现依据文档，不承担排期职责。

## 4. 影响面

| 项 | 影响 |
|---|---|
| 代码 | 无。三处均为文档内的任务引用，不改任何实现路径 |
| 排期 | 无。03 的依赖图与周计划不变 |
| 后续任务 | T10 / T21 / T22 执行时按 03 口径认领即可，不会重复或漏做 |

## 5. 裁决结果

**头头 2026-11-26 批准 §3 方案**：以 `03-delivery-plan.md` 为任务编号唯一真值源，按 §3 修改 02 文档的交叉引用。
